# HammerForge Spec

Last updated: October 22, 2026

This document describes HammerForge's architecture and data flow.

## Goals
- Fast in-editor greyboxing with brush workflows.
- Editor responsiveness by avoiding live CSG.
- Reliable bake pipeline and clean data model.
- Modular codebase with clear separation of concerns.

## Architecture

HammerForge uses a coordinator + subsystems pattern. `LevelRoot` is the public level facade and coordinator that owns container nodes, exported properties, signals, runtime setup, and cross-system coordination. Concrete subsystems receive a reference to `LevelRoot` in their constructor. Export templates eagerly construct only the brush, entity, bake, paint, and file core; editor builds dynamically load the authoring graph. Default editor UX is the core loop (Draw → material → entity → bake → Test Level); radial menu, coach marks, and operation replay install only when `power_user_overlays` is enabled.

### Signals (Central Registry)
All signals are defined on `LevelRoot`. Subsystems emit them via `root.<signal>.emit(...)`. UI and other consumers subscribe instead of polling.

| Signal | Description |
|--------|-------------|
| `bake_started` | Emitted when a bake begins |
| `bake_progress(value, label)` | Progress 0..1 with short label during bake |
| `bake_finished(success)` | Emitted when a bake completes |
| `grid_snap_changed(value)` | Grid snap updated |
| `active_material_changed()` | The Active Material changed, from the dock, the Inspector or a script |
| `transform_pivot_changed()` | `transform_pivot_mode` or `transform_pivot_point` changed, from the dock, a pick, a load or the Inspector |
| `settings_applied()` | The level's settings were set all at once: a `.hflevel` load, its undo or redo, or the undo or redo of a dock cordon edit. The dock reads every setting again |
| `brush_added(brush_id)` | A brush was created |
| `brush_removed(brush_id)` | A brush was deleted |
| `brush_changed(brush_id)` | A brush was modified (transform, material, etc.) |
| `entity_added(node)` | An entity was added (place, restore, duplicate) |
| `entity_removed(node)` | An entity is about to be removed, emitted while the node is still valid |
| `paint_layer_changed(layer_index)` | A paint layer was modified |
| `paint_stroke_committed(changed_cell_count)` | A floor paint stroke was committed |
| `state_saved()` | `.hflevel` save completed |
| `state_loaded()` | `.hflevel` load completed |
| `autosave_failed(error_message)` | An autosave failed, either the threaded write or a region sidecar |
| `hflevel_save_completed(path)` | A manual `.hflevel` save finished successfully |
| `hflevel_save_failed(path, error_message)` | A manual `.hflevel` save failed |
| `user_message(text, level)` | Subsystem-to-dock notification routing (0=INFO, 1=WARNING, 2=ERROR) |
| `material_list_changed()` | Material palette updated (add/remove) |
| `face_selection_changed()` | Face selection changed (snapshot comparison) |
| `material_used(material)` | A material was just applied to faces or brushes by an edit: a Paint click, a face assign, a browser drop, a favourite, Apply Last Texture, Apply Picked Look or the agent bridge. Undo and redo do not emit it. The browser's Recent row follows it (#1422) |

LevelRoot holds no object selection: Godot's `EditorSelection` does. The dock's own `selection_clear_requested` signal asks the plugin to clear its mirrored selection before the dock clears `EditorSelection`.

## Visgroups + Grouping

### Visgroups (Visibility Groups)
- Named groups (e.g. "walls", "detail") with per-group show/hide.
- Membership stored on nodes via `node.set_meta("visgroups", PackedStringArray)`. A node can belong to multiple visgroups.
- A node in ANY hidden visgroup becomes hidden (Hammer semantics). Nodes not in any visgroup are always visible.
- `HFVisgroupSystem` manages CRUD, membership, visibility refresh, and serialization.
- Visgroups persist in `.hflevel` via `capture_visgroups()` / `restore_visgroups()`.

### Grouping
- Persistent groups that select and move together.
- Single group per node via `node.set_meta("group_id", group_name)`.
- Clicking a grouped node expands selection to all group members.
- Ctrl+G groups selection, Ctrl+U ungroups.
- Groups persist in `.hflevel` via `capture_groups()` / `restore_groups()`.

## Texture Lock
- Planar UVs project from a vertex's position in the level, not in its brush, so `uv_offset` is an offset from the world grid. A brush that moves with no compensation keeps its place in the level and the texture slides under it; the compensation below is what holds the texture on the brush. Cylindrical stays in the brush's own space and is not compensated.
- The brush tells its faces where it is from `NOTIFICATION_LOCAL_TRANSFORM_CHANGED`, as its own transform is set, from `NOTIFICATION_TRANSFORM_CHANGED`, a frame after a parent moves, and from `rebuild_preview()`. The last covers the paths that fill `faces` by appending rather than assigning, so the setter never fires: `apply_serialized_faces()` on a load or an undo restore, and the bevel, inset and vertex tools adding faces to a brush already placed.
- When `texture_lock` is enabled (default), moving or resizing a brush automatically compensates face UV offset and scale.
- Per-projection-axis math in `face_data.gd:adjust_uvs_for_transform()`:
  - PLANAR_X: projects (z, y), PLANAR_Y: projects (x, z), PLANAR_Z: projects (x, y).
  - BOX_UV resolves to the planar axis matching the face normal.
  - FACE reads the face's own axes, U level along it and V down its slope (#1419).
  - CYLINDRICAL is skipped (complex, future enhancement).
- A face in a texture group (`FaceData.uv_group`, #1437) is not compensated: it keeps its group's mapping, and a group last fitted is fitted again (`HFBrushSystem.refit_texture_groups()`).
- Texture lock holds a texture on the brush, for a turn as well as for a move. Since #652 the projection follows the level, so no compensation at all leaves a texture where it is in the world, and the compensation is what carries it round. Before #652 it was the other way about, which is what #355 settled and #653 and #684 corrected.
- Position compensation: `uv_offset -= projected_delta.rotated(uv_rotation) * uv_scale`. The UV transform rotates before it scales and offsets, so the projected move is rotated the same way. `hf_carve_system.gd` uses the same expression.
- Size compensation: `uv_scale *= inverse_size_ratio` per projection axis.
- Rotation compensation: `adjust_uvs_for_rotation()` reads the old projection at `local_rot.inverse() * v`, cancelling the turn the projection already carries. It only answers for a turn that keeps the projection plane; a turn that does not returns false.
- Axis handedness: `projection_axes()` is right handed for PLANAR_Z against its own normal and left handed for PLANAR_X and PLANAR_Y. A face that changes axis under a turn would therefore come back mirrored, so `reconcile_box_uv_axis()` folds the flip into `uv_scale` at the moment the axis changes, comparing the old axes carried through the turn against the new ones. It holds the brush orientation the UVs were laid out against, which is transient: the first orientation a face is told is its layout, so a reopened level reconciles nothing.
- Hook in `hf_brush_system.gd:set_brush_transform_by_id()` captures old transform, applies new, then adjusts UVs.
- HammerForge move, nudge, floor/ceiling, and resize paths use that boundary. Godot's native Node3D transform widget intentionally leaves face UV resources unchanged, because its native undo action does not capture those nested Resource edits. Since the projection is world-space, leaving them unchanged means a brush moved with the native widget behaves as though Texture Lock were off: the texture keeps its place in the level and the brush slides under it.

## Cordon (Partial Bake)
- Restricts bake to one or more AABB regions. A brush that touches any of them is baked; the rest are skipped.
- Properties on LevelRoot: `cordon_enabled: bool` switches them all, `cordon_aabb: AABB` is the first cordon, and `cordon_extra_aabbs: Array[AABB]` holds the rest. Each setter stores a region: a negative size is turned the right way out, and a box with a non-finite corner is refused.
- Each cordon has a name and its own switch: `cordon_names: PackedStringArray` and `cordon_active: Array[bool]`, in cordon order. An empty name, or one past the end, shows as "Cordon N"; a switch past the end is on. Both lists drop trailing defaults, so a level that never used them keeps them empty.
- `get_all_cordon_regions()` returns every cordon, on or off, the first one first, and is what the wireframe and the dock read. `get_cordon_regions()` returns the ones switched on, and is what the bake reads. Both read a box appended to `cordon_extra_aabbs` in place, which skips the setter, as a region.
- `set_cordon_active(index, on)`, `set_cordon_name(index, name)`, `is_cordon_active(index)` and `get_cordon_name(index)` read and set one cordon's switch and name. `capture_cordons()` and `restore_cordons()` take and put back every cordon at once.
- `set_cordon_region(index, box)` and `remove_cordon_region(index)` edit the list. Index 0 is `cordon_aabb`, and the index one past the last adds a cordon. The last cordon cannot be removed; removing the first moves the next one up. A cordon's name and switch move with it.
- Filter applied in `hf_bake_system.gd`: `collect_chunk_brushes()`, `append_brush_list_to_csg()`, `_append_face_bake_container()`, and the dry run through `brush_bakes()`.
- Helper `_brush_in_cordon()` computes brush world AABB, grown by `HFBakeSystem.CORDON_TOUCH` (1 mm) so a face that lies on a cordon's face touches it, and tests intersection with every cordon that is on. A cutter outside every cordon is taken when it touches a structural solid a cordon took, so the partial bake keeps the cuts in what it takes (#1206). With every cordon off it takes every brush, as with `cordon_enabled` off.
- "Set from Selection" fits the chosen cordon to the merged AABB of selected brushes + 1.0 margin. "Add from Selection" adds a cordon the same way. Both go through `set_cordon_from_selection(nodes, index)`, which switches that cordon on.
- Yellow wireframe visualization via one ImmediateMesh (12 edge lines per cordon, unshaded, no depth test). A cordon that is off is drawn with a fainter vertex colour.
- `cordon_extra_aabbs` and `cordon_active` are bake settings: they are in `BAKE_SETTING_NAMES` and in the change tracker's bake configuration, so a changed cordon rebuilds on the next bake. The four cordon bake settings are named once, in `HFBakeSystem.CORDON_BAKE_SETTINGS`; the bake and scope lists, the change tracker and the dock all read it through `is_bake_setting()` or the lists.
- The dock is where cordons are added and removed. The Inspector shows `cordon_extra_aabbs` read only and keeps `cordon_names` and `cordon_active` out of sight (`@export_storage`), because removing a box there alone left the names and switches after it on the wrong cordons. The change tracker reads saved properties as well as shown ones, so a switch a script sets still rebuilds.
- Play Selected Area bakes the selection alone. The dock sets the extra cordons aside and switches the first cordon on for its bake, then puts every cordon, name and switch back through `capture_cordons()` / `restore_cordons()`. The playtest run clears the extra cordons and the switches when the launch request names an area. When the spawn check stops it, `show_spawn_fix_dialog()` gets the same `cordon` override, so Fix & Play and Play Anyway still play the area. Play from Camera hands the dialog its start pose the same way, and there Fix & Play moves that pose, not the authored spawn, and records no undo step (#1010).
- Cordon settings persist in `.hflevel`.
- Every dock cordon edit is one undo step on the scene history: `HFDockVisgroupHandler.record_cordon_edit()` registers `restore_cordons()` with the cordons after the edit as the do and the cordons before it as the undo, and registers nothing for an edit that changed nothing. Spin edits to one cordon merge (MERGE_ENDS). `restore_cordons()` tags a full reconcile and emits `settings_applied`, which the dock answers by reading every setting again; `apply_hflevel_settings()` emits it too, so the dock follows a load and its undo.

## Bake Profiles
- A bake profile is a set of values for `HFBakeSystem.profile_setting_names()`: every name in `BAKE_SETTING_NAMES` except `SCOPE_SETTING_NAMES` (`bake_visible_only` and the four cordon settings), which decide what is baked rather than how. The list is derived, so a new bake setting joins profiles on its own. Every profile setting is a bool, int or float, so a profile goes to JSON.
- `HFBakeProfiles` (`hf_bake_profiles.gd`) holds two built-ins from the shipping guide's table: Editing sets `bake_merge_meshes` and `bake_generate_lods` off, Shipping sets them on. Both set the same keys, so switching back and forth loses nothing.
- Saved profiles live in `HFUserPrefs` under `bake_profiles`. `read_saved()` holds each to the level's property types through `HFBakeSystem.profile_value()`. Whole-number floats from JSON come back as ints. A value of the wrong kind, a setting that is not a profile's, or a reserved name (Editing, Shipping, Custom, in any case) is dropped with a warning naming the profile. A profile left empty is dropped too, because an empty profile would match every level. A number past a setting's range is held to it on read, with a warning naming the profile: `validated()` sets it on a new level of the same script, never added to the tree, and keeps what that level's setter makes of it, so the profile holds what the level becomes when it is picked (#1207).
- A project shares profiles through `<presets_dir>/bake_profiles.json` (`HFBakeProfiles.PROJECT_FILE`, `{"version": 1, "profiles": {...}}`). `read_project()` holds them to the level as `read_saved()` does. `combined()` puts both sets together, and on a name both hold the project's wins, with a warning naming the hidden copy. `write_project()` writes sorted keys, one option a line; Save and Delete start from `read_project_raw()` and change one entry, so a profile this machine cannot read stays in the file. They first ask `project_file_unreadable()`, true for a file that is there but does not parse as a profiles file, and refuse with a status line rather than write what they read of it, which is nothing. `write_project()` returns false when `store_string()` does. The dock marks project profiles "(project)" and keeps the name in the item's metadata. A **Project** checkbox sends Save and Delete to the file; saving to the project drops this machine's copy of that name, and saving here under a project profile's name is refused.
- Which profile a level is on is never stored. `current()` returns the profile whose every value the level has (floats compared with `is_equal_approx`), the one setting the most options when several match, or "" (shown as Custom).
- `LevelRoot.capture_bake_options()` takes every profile setting. `apply_bake_options(values)` sets the ones named through `HFBakeSystem.apply_profile_options()`, then tags a full reconcile and emits `settings_applied`.
- A switch from the dock is one undo step on the scene history: `HFDockManageHandler.record_bake_profile()` registers `apply_bake_options()` with the options after as the do and before as the undo, and nothing when nothing changed. Saving and deleting a profile change the preferences or the project's file, not the level, and are not undoable. Delete takes two presses of the same name.
- Export Game Scene bakes on the profile picked under **Export with** (`dock.export_profile_opt`, filled by `HFDockManageHandler.sync_export_profile_ui()`, Shipping to start; the first entry, metadata "", keeps the level's own options). `on_export_game_scene()` takes `capture_bake_options()`, applies the picked profile, bakes and exports through `_bake_game_scene()`, then applies the captured options again on success and failure alike. `_bake_game_scene()` bakes through `LevelRoot.bake_whole_level()`, which switches `cordon_enabled` off for the bake and puts the cordons back after it through `restore_cordons()`, keeping any cordon setting changed while it baked, so a cordon left on does not cut the game scene down (#1205). No undo step is registered. While that bake runs, `dock.bake_options_held()` is true: it asks that the exported level is the dock's level and still `is_bake_in_flight()`, so an export that never comes back cannot hold for good. The dock's setting handlers then refuse a change to any `profile_setting_names()` option and `on_bake_profile_selected()` refuses a pick; each sets the controls back from the level and toasts why (#1011). The Inspector and scripts are not held. Instead the export compares the options with the ones it baked with, and `options_set_during_export()` names any that changed meanwhile; those are left as set rather than put back, with a toast naming them (#1020).

## Brush Workflow
- Draw creates DraftBrush nodes in DraftBrushes.
- Subtract brushes are staged in PendingCuts until Apply Cuts.
- Extrude Up/Down picks a face via `FaceSelector`, creates a preview brush along the face normal, and commits a new DraftBrush on release. Uses `HFExtrudeTool` (RefCounted).
- **Hollow** (Ctrl+H): shells a brush into walls of a configurable thickness, by running `HFConvexClip.progressive_remainder()` over the brush's own face planes pushed inward. One face gives one wall, so a box yields six and a cylinder yields a tube. Each wall's outside keeps the solid's textures, surface paint and sculpts, as for Clip. Works on any convex brush at any rotation. Refuses a thickness that leaves no interior, brushes with more than `HFConvexClip.MAX_BOOLEAN_PLANES` distinct planes (a sphere built from Godot's default mesh would have shelled into thousands of walls; round brushes are built from 128 faces by default since #1057), and a brush that is not convex (`HFConvexClip.is_convex_solid()`), such as a torus, whose walls would follow its hull. A hollow is live: the record in `HFBrushSystem._hollows` keeps the solid the walls were shelled out of (the one thing not recoverable from the walls), each wall's placement, and the thickness, so selecting any wall turns the Hollow row into **Re-hollow** with **Detach** beside it. `update_hollow()` rebuilds the solid and plans the new walls on it before deleting the old ones, so a refused thickness leaves the level untouched; a room whose walls all share one move re-shells where it now stands, and walls moved individually disagree and leave the placement alone. Records without wall placements — none exist yet, but a level written before this would have them — answer "no move" rather than needing migration. The record also keeps the shape signature each wall was made as, so `edited_hollow_walls()` can count the walls a re-shell would rebuild over: a wall that no longer matches its signature, or that stands off its recorded placement when the walls disagree about where the room is. A relocation counts nothing, because the re-shell follows it. The dock names the count beside Detach and makes Re-hollow ask twice, keyed on the hollow and the thickness, the way the array section does. The signature is `HFDuplicator.shape_signature()` — values only and serializable, and deliberately blind to weight-image contents for the cost reason recorded there. Since walls inherit their solid's paint layers (#863), a stroke inside one of those changes nothing the shape signature reads, so the record also keeps `wall_paint`, each wall's `HFDuplicator.paint_signature()`: the engine's hash of every weight image, read in no particular face order, which a hollow can afford and an array cannot (#869). A record without `wall_paint` answers "cannot tell" for strokes, like the other two fields. The shape signature lists faces and corners in order, and a box rebuilds when its scene opens, so a box wall is stored the way that rebuild makes it (`DraftBrush.faces_in_box_order()`) and a save and reopen counts nothing (#873). A record taken before that lists the old order and counts every wall after a reopen until one Re-hollow.
- **Structure section** (Ctrl+Shift+A, dispatched from the dock, the command palette and the viewport): builds whatever type the section is showing, placed on the selection or the world origin. `HFDockBrushHandler.create_placement()` is the single definition of where a new structure lands — `resolve_transform_pivot()` for the origin and `resolve_selection_basis()` for the facing — and the structure ghost reads the same function, so the angle is visible before the button is pressed. A selection only hands its facing over when every part of it agrees; a disagreement, or a basis that is not a pure rotation (`HFTransformSystem.is_rotation_basis()` — mirrored or scaled), answers with the world axes rather than building through a basis that would invert face winding. The shortcut keeps the action id `create_arch` so existing custom keymaps still resolve. `HFGeneratorSystem.can_build()` is asked before any undo action is opened, because each field can be in range while the combination is not — a wall as thick as the arch is wide, an arc of zero, a wide arc across too few segments. A refused build says why and records nothing.
- **Arch** (`HFArchBuilder`): turns radius, wall thickness, depth, arc degrees, segment count and start angle into one brush per voussoir. Winding comes from `HFConvexClip.orient_faces_outward()`.
- **Stairs** (`HFStairsBuilder`): a flight, one brush per step, filled to the base or floating at the tread thickness, straight or turning L or U at a landing. `ramp_collision()` gives the slope a bake lays in place of the steps when Collision is Ramp, and `HFSpiralStairsBuilder` has one too.
- **Spiral stairs** (`HFSpiralStairsBuilder`): annular treads about an axis, with an optional octagonal newel post. A tread is capped below half a turn, like an arch segment, because a wider wedge is not convex.
- **Dome** (`HFDomeBuilder`): a hemisphere in rings, one brush per panel, with adjustable arc and sweep and a wall that may reach the radius for a solid dome. Built in rings because a patch of sphere is not planar; a conical frustum band is. Capped at `MAX_PANELS` brushes.
- **Ring** (`HFRingBuilder`): a tube polygon of 3 to 32 sides swept round the Y axis, one brush per segment, each joining the polygon at one angle to the same polygon at the next. The two are mirror images across the plane between them, so every side is a flat trapezoid; a piece is capped below half a turn like an arch segment, and a tube radius at or past the radius is refused.
- **Door Frame** (`HFDoorFrameBuilder`): two box posts and a box lintel, or an `HFArchBuilder` half circle lifted onto the posts, round a clear opening of Width by Height, standing Proud of each face of a Wall. With Cut opening on, the last piece is the cut for the opening, one convex prism (an arched one is the box to the springing line and the arch's inside polygon over it), and `cutter_pieces()` names it. `HFGeneratorSystem.cutter_pieces()` asks any builder that answers it, and `HFBrushSystem.create_brushes_from_face_sets()` makes those pieces Cutouts: pending on create, and on an Update pending or applied as the structure's cut was. The rebuild carry keys a cut by its place among the cuts and a solid by its place among the solids, so a head of a different piece count never hands a cut a solid's look or name.
- **Trim Run** (`HFTrimRunBuilder`, #1414): the one structure built along something in the level rather than about its own origin, so it is in `HFGeneratorSystem.structure_types()`, which the dock lists, and not `known_types()`, which every check that builds a type from its defaults reads. `HFGeneratorSystem.trim_run_from_faces()` reads the faces picked in Face Select: each upright face less what another union brush just in front of it covers (a Trim Run's pieces excepted), its bottom and top edges where that leaves them level, chained end to start into runs with the face's outward side on the right of travel, and every Cutout's outline where it takes away the wall just behind a face. The run is plain data on `HFGenerator.run`, both edges at once, so an Update with another Edge needs no Re-pick, and the doorways are outlines rather than gaps, because whether one breaks the trim depends on its Offset and Height. `build_along()` sweeps each of the bands `hf_trim_profile.gd` cuts the profile into along a run with `HFPathSweep`'s mitred cuts, and a stretch that stops at a doorway ends on `HFPathSweep.square_cut()`. `can_build()`, `create()`, an Update (`can_rebuild()`) and `repick()` all ask the builder's `check_along()`, which names a face too short for the trim to turn its corners.
- **Structure presets** (`HFStructurePresets`): named settings per type in `res://hammerforge_presets/structure_presets.json`. A preset is read through `HFGeneratorSchema.check_ranges()` (a bad value refuses the whole preset, naming the field) and `merge()` (unknown keys dropped, missing ones defaulted). Picking one fills the Structure section's fields only.
- **Live generators**: every structure is created through `HFGeneratorSystem`, which records its type, settings, placement and the brushes it made. Selecting a piece turns the dock's Structure section into an editor for it — the type dropdown follows the selection, the settings load, **Update** rebuilds in place preserving appearance by index, or by direction on a box piece — the whole-brush `material_override` and, per face, `material_idx`, UV projection, scale, offset and rotation, custom UVs and paint layers — and each piece's node name and brush entity (`HFBrushEntity.carried()`), with a piece past the old count joining the entity the whole structure was (#1163, #1165) and taking the whole-brush material most pieces had (#1526), and **Detach** forgets the record and leaves ordinary brushes. Where a rebuild cannot line the pieces up, `appearance_at_risk()` names the painted pieces that would be dropped and the section warns before a second press goes ahead. Validation runs before any deletion, and deletion checks each brush's `hf_generator_id` rather than trusting the record's id list. Update first asks `HFGeneratorSystem.update_changes_nothing()`: settings that build what the record's build (`same_settings()` reads both through the schema's merge, floats nearly equal), and every piece still there, still the structure's and unedited. Then nothing is rebuilt and no step is recorded, so every piece keeps its id (#1368). The dock commits Update with an absolute redo, so a redo gives back the ids the Update made (#1275).
- **Relocation and hand edits**: each record keeps a per-piece signature of where the piece was put, how it was turned, and a hash of what it is. Where a structure went is decided by vote, not unanimity: surviving pieces are grouped by the rigid transform they received — a turn, a slide, or both — and a group holding more than half the voters is the relocation, composed onto the placement so the structure rebuilds where it now stands and at the angle it now has. Pieces outside that majority were edited individually. Unanimity was the earlier rule and was strictly worse: one nudged brush of a twelve-piece arch overruled the eleven that agreed, reported twelve hand edits instead of one, and carried the structure back to its creation placement on the next Update. When no majority exists and pieces have plainly moved, `pieces_disagree_about_placement()` is true and the Structure section says the structure cannot be located rather than counting shapes. A move that is not rigid answers no: a squash is not a relocation, and a mirror is refused outright because rebuilding through a negative-determinant basis would invert the winding of every face and not look wrong until the bake. A piece is counted as edited when its shape hash differs — asked in the basis it was *recorded* in, so a structure turned as a whole is not mistaken for a structure reshaped by hand — or when its transform is not where the relocation would have put it. Signatures written before piece bases existed have none; the reader answers a missing basis with the placement's own, which is what every piece the generator built was given, so an older record recovers a turn without a migration.
- **Construction plane**: `LevelRoot._raycast()` picks a brush face first and otherwise answers with the plane the grid is drawn on — `HFGridSystem.intersect_axis_plane()` at `effective_grid_axis()` and `grid_plane_origin`, which is what `record_last_brush()` moves and what an axis lock stands up on X or Z. The static `construction_plane_intersection()` (the horizontal plane through the world origin) remains as the answer when no grid system is loaded, which is every exported game. Before this the static answered everything, so the grid moved to the last brush and the next brush did not follow it, and a side view onto an axis-locked grid returned no hit at all because a horizontal plane is parallel to a horizontal ray.
- **Overlay space**: every overlay node is a child of `LevelRoot`, so a mesh instance's *local* transform is in the root's space, not the world's. What the overlays are handed is almost all world-space — a brush's own `global_transform`, a plane built from `world_bounds_of()`, an intersection from `world_aabb()`, a cordon volume in world coordinates, two entities' `global_position`, `get_all_vertex_world_positions()` — so each is pinned to world space, either by assigning through `global_transform` (the previews, which carry a placement) or by setting the instance's `global_transform` to identity when its vertices are already world coordinates (the cordon wireframe, the I/O visualizer, the vertex/edge overlay, the prefab ghost). The one exception is `HFSubtractPreview`'s CSG results: `get_meshes()` reports transforms relative to a combiner parented to `LevelRoot`, so those are already in the root's space and stay local. `get_meshes()` itself returns a flat `[Transform3D, Mesh]` pair rather than a list, which the baker read as a list and so dropped the transform from; `Baker._csg_mesh_pairs()` is now the one place that reading happens. `tests/test_preview_placement.gd` holds the property for every overlay with the root both moved and turned; an assertion that the mesh is non-empty is part of it, because an overlay that drew nothing has its bounds at the origin and can pass by accident.
- **Placement space**: a `Node3D` that is not yet inside the tree has no parent to measure against, so assigning `global_position` or `global_transform` writes the local transform instead, and Godot logs an out-of-tree error on the read side. Anything created from world coordinates is therefore parented first and positioned second: `place_brush()` after the draft or pending container adopts the brush, `create_brush_from_info()`, `create_default_spawn()`, and `create_entity_from_map()` after `add_entity()`. `restore_entity_from_info()` assigns after `add_child()` and before it emits `entity_added`, so a listener never sees the entity at the wrong place. The bake path is the same rule: `append_brush_list_to_csg()` adds each CSG stand-in to the combiner before assigning `global_transform` from its draft brush (or, for a CUSTOM brush cut with its own mesh, from the mesh instance the mesh belongs to), because the combiner is itself a child of `LevelRoot` and an early assignment would apply the root transform twice, to the rotation as well as the origin. This matters whenever `LevelRoot` is away from the world origin, which is the case the ordering bugs were only ever invisible in. `tests/test_brush_system.gd`, `tests/test_entity_props.gd` and `tests/test_bake_system.gd` hold the property with the root translated, and the bake pair with it turned as well.
- **Brush names**: a brush created without a name is named for its shape and the number its id ends in, such as `Box_12` or `Wedge_3` (`HFBrushSystem._readable_name()`, #1050). A saved or authored name is kept, and a sibling with the same name makes Godot number the new one on. Before this every brush had Godot's own name for an unnamed node, `@Node3D@25154`, in the Scene dock, the saved scene and Validate's messages.
- **Entity names**: an entity added under a name a sibling has, as every one dropped, imported from a `.map` or loaded with an example after the first is, is numbered on readably, `DraftEntity2` (`HFEntitySystem.add_entity()`, #1179). Godot's own name for it was `@Node3D@14`, which `Node.name` will not take back, so a restore made it `_Node3D_14`.
- **Array preview and budget** (`HFArrayPreview`, `HFDuplicator`): `HFDuplicator.CopyPlacement` is the one definition of where an array's copies go, and `linear_placements()` / `radial_placements()` / `grid_placements()` are what both `generate*()` and the ghost read, so what is drawn and what is built cannot drift. `can_generate()` caps an array at `MAX_COPY_BRUSHES` (256 — the same budget and currency as `HFDomeBuilder.MAX_PANELS`), naming the count that was asked for; the grid controls reach 32 cells a side, which is over thirty-two thousand brushes. The dock asks it before opening an undo action and before drawing. The ghost is armed by touching an array control rather than by selection, because the array controls share an always-open section with a dozen other tools; it is disarmed by creating the array, an empty selection, or leaving the Build tab.
- **Structure preview** (`HFStructurePreview`): the Structure section draws what its numbers would build before the button is pressed, and for a selected structure it draws the rebuild standing over the real pieces at `rebuild_placement()` — the recorded placement plus the relocation delta, so a structure that was dragged previews where it now is. Settings the builder refuses draw nothing and put the refusal in the section's message line. The ghost is gated on the section being expanded and the Build tab being current, cleared once a build or rebuild has happened, and destroyed with its `LevelRoot`.
- **Settings schemas** (`HFGeneratorSchema`): each builder describes its own settings, and the dock builds its controls from that description. `HFGeneratorSystem.builder_for()` is the only place that maps a type name to a builder.
- **Clip** (Shift+X): splits a brush along a plane into two new brushes, via `HFConvexClip.split()`. The plane is taken into the brush's own frame, so any convex brush at any rotation cuts, and both pieces inherit the original transform. A piece that is still an axis-aligned box in that frame (`HFConvexClip.is_axis_aligned_box()`: one face on each side of its bounds, each holding that side's four corners and facing out of it, and no side under `HFConvexClip.MIN_BOX_SIDE`, 0.1, #1607, #1598) is emitted as a BOX and keeps its resize handles, its faces stored the way the box builder makes them so a rebuild changes nothing (#867); anything else becomes CUSTOM with the split faces as authoritative geometry. With no plane picked, the Clip button and Shift+X split on Y across the middle of the brush's world bounds, snapped (`default_clip_position()`, #1024). `clip_brush_by_plane()` takes an arbitrary world plane; `clip_brush_to_face_plane()` cuts along the plane of a selected face. **Clip to Face Plane** (Shift+Alt+X) reads that plane once and commits the whole selection through `clip_brushes_by_plane()` as a single undo action, carrying the cut as a `Plane` rather than a brush id and face index, so a redo still works when the reference brush was itself one of the targets. It takes the object selection saved on the way into Face Select, since Face Select clears the live one, and releases both selections afterwards. Preserves material, operation, visgroups, group ID, Cast Shadows and Lightmap Scale (#1660), and every piece is the brush's whole brush entity (`HFBrushEntity.carried_into_pieces()`): its class, name, tie, properties and I/O wiring, with a new tie when it had neither a name nor a tie, so a door cut in two is one door (#1194). Each piece face keeps its face's surface paint in layers of its own, and a sculpt follows onto every four-cornered piece, resampled by `HFDisplacementData.resampled_onto()` so each grid point stays on the original surface. `HFConvexClip.carry_surface_detail()` does both once the cut is kept, never in the preview; a sculpt that cannot follow is dropped with a warning naming the brush (#863).
- **Move to Floor/Ceiling** (Ctrl+Shift+F/C): raycasts against other brush AABBs to snap selection vertically.
- **Carve** (Ctrl+Shift+R): boolean-subtract one brush from every shown brush it intersects. A brush that is hidden, or in a hidden visgroup, is left alone, and the confirmation and the result count the ones skipped (#1710). `HFCarveSystem` runs progressive remainder over the carver's own face planes: for each plane, split what is left of the target, keep the half outside as a finished piece, and carry the half inside to the next plane. What survives every plane is the intersection, which is what the carve removes. Because the planes come from the carver's real faces rather than the six sides of its bounding box, the carver and its targets may be rotated, cylinders, merged brushes, or anything else convex. A carver that is not convex, such as a torus, is refused (`HFConvexClip.is_convex_solid()`), since its planes describe its hull. Preserves material, operation, visgroups, group_id, and the brush entity, as Clip does. Paint and sculpts are carried as for Clip, from the target's original face however many planes cut it, since `progressive_remainder()` returns `origins` chained back to that face.
- **Merge** (Ctrl+Shift+M): combines 2+ selected brushes into a single CUSTOM brush. Transforms all face `local_verts` through the full `Transform3D` pipeline (source local → world → merged local via `affine_inverse()`), so rotated/scaled brushes merge correctly. The merged brush is the convex solid the brushes make together (`HFConvexClip.union_of()`), so two boxes sharing a face become one six-faced box with no face where they touched; each face keeps the look, UVs and paint of the largest source face on its plane, and its sculpt only if it is that source face whole (#1200). Per-brush `material_override` is registered into MaterialManager and stamped as per-face `material_idx`. Validates same operation type, that the brushes are one brush entity or all plain geometry (`HFBrushEntity.are_one_entity()`), that they touch, and that what they make is convex (an L or a doorway is refused); the merged brush is that entity, with every wire and property any of them held (#1194). Inherits visgroups and group from the first brush.
- **Intersect** (Ctrl+Shift+I): keeps only the volume 2+ selected brushes share (#1426). `HFCarveSystem.intersect_brushes_by_ids()` runs the same progressive remainder as Carve with the first brush as the target, over the planes of each other brush in turn, and keeps the remainder Carve throws away; two convex solids overlap in a convex solid, so the result is one brush. It is built as a piece of the target (operation, material, visgroups, group, brush entity), with paint and sculpts carried from the target's faces through the chained `origins`. A face that is no piece of a target face lies on another brush's plane and takes that brush's face look through `FaceData.copy_appearance_from()`, with Custom and Cylindrical UVs read off that face at its corners; when a face would then show another brush's material override, every override is turned into a palette slot as Merge does. Refused before anything changes when the brushes share no volume, mix operations, are not all one entity, or one is not convex. Every source is replaced in one undo step.
- **Rotate** (R / Shift+R): turns the selection by `rotate_snap_degrees` about the axis lock, or Y when none is set. Pivots on `transform_pivot_mode`: the selection's origin centroid, the world origin, the active object, or `CUSTOM`, the point in `transform_pivot_point` that Pick Pivot (Alt+P) sets from a clicked vertex, edge midpoint or face centre (#1442). The centroid is used rather than a bounding-box centre because it is exactly invariant under rotation about itself, so repeated presses cannot walk the selection. With `texture_lock` on, every face's `uv_rotation` is compensated.
- **Flip** (Shift+M): mirrors the selection across an axis-aligned plane. A world reflection `R` gives a determinant `-1` basis, which would invert triangle winding at bake; the transform is composed as `R * basis * H` with `H` a reflection along the local axis most aligned with the mirror normal, restoring a positive determinant while leaving world vertices exactly mirrored. A primitive that `H` maps onto itself keeps its shape and resize handles; otherwise the faces are promoted to `CUSTOM`, their `local_verts` reflected by `H` and their vertex order reversed. A displacement grid is relabelled to follow its face's corners (`HFDisplacementData.remapped()`), its custom offsets reflected by `H`, and `flip_diagonals` turned over so each cell keeps its fold. A primitive's faces keep the corner order they had at each place, so the saved faces are the ones the shape generates. A resize hands each rebuilt face the old face's data by index, and for a face carrying a grid or custom UVs it first finds the turn that lines the old corners up with the new ones, measured as fractions of each brush's bounds, and relabels the data to match (`FaceData.relabel_corner_data()`). A quarter turn swaps the diagonals as well, so a resize can set `flip_diagonals` on a sculpt that was never mirrored.
- **Mirror Copy** (Alt+M): `HFTransformSystem.mirror_copy()` keeps the selection and adds a copy across each axis set in `mirror_copy_axes` (bits X 1, Y 2, Z 4) and each combination of them, 2^n - 1 copies. Each copy is Duplicate's record with no offset and fresh identities (`HFBrushEntity.fresh_identities()`), built one combination at a time so names stay free, then put through `flip()` once per axis, so it carries Flip's fold, face data and mirrored angles. The planes cross each axis at the transform pivot, or at the far (+) side of the selection's bounds under `mirror_copy_at_edge`. With `texture_lock` on, `FaceData.adjust_uvs_for_mirror()` folds the reflection into each planar face's scale, rotation and offset so the copy shows the mirror image. One undo step through `HFUndoHelper.commit_completed()`, and the copies join the selection.
- **Reset Rotation** (Alt+R): clears a brush's rotation, keeping its origin, its size and its scale. A basis is rotation times scale, so the cleared basis is `Basis.from_scale(basis.get_scale())` rather than the identity — a brush scaled with Godot's own gizmo has no rotation to clear and is left alone. When the basis is a signed axis permutation and the brush is a BOX, the swap is folded into `size` first, with the scale carried along, so a quarter turn is cleared losslessly. Hollow, Clip and Carve all work in a brush's own frame now, so this is a tidying command rather than a prerequisite for any of them.
- **Arrays**: `HFDuplicator` supports linear, radial (count / axis / step degrees / pivot) and grid (per-axis cell counts and spacing) layouts. Radial copies compose their transform through `HFTransformSystem.rotated_transform()`. A serialized duplicator without a `mode` key loads as linear. All three layouts commit through `HFUndoHelper`, so Ctrl+Z takes the copies back out. An array is live: `duplicator_for_selection()` resolves a record from either a source (`duplicator_id`) or a copy (`duplicator_instance_of`), and the dock's Duplicate Array section becomes an editor for it — Create becomes **Update Array**, with **Detach** beside it. `update_duplicate_array()` runs `HFDuplicator.regenerate()`, which clears the copies and lays them out again under the same `duplicator_id`, each copy a brush entity of its own (`_spawn_copies()`, #1161), so an array can be tuned repeatedly without reselecting; `detach_duplicate_array()` strips both tags and erases the record without touching a brush. An array being edited takes its sources and its pivot from its own record rather than from the selection, because the piece under the cursor is usually a copy. The 256-brush budget is asked before the rebuild, so a refused update deletes nothing, and a state restore re-tags copies as well as sources. What an Update would undo is said before it does it: `expected_copy_transforms()` recomputes each copy's placement from the live sources through `placements_for()` — recording nothing — and `relocation_vote()` reads the result the way `HFGeneratorSystem._relocation_vote()` reads a structure's, so the move most copies agree on carries the array and the copies that disagree are counted as hand edits. A source that moved is reported separately and does not gate the button; hand-edited copies gate it behind a second press keyed on the array and the settings. Shape is read the same way: `reshaped_copy_ids()` groups the copies by a value-only signature — no resource identity, since each copy holds its own equal-but-separate `FaceData` and weight image — and the copies outside the largest group are the edits, so repainting the *source* is not read as every copy being edited. Weight-image contents are excluded deliberately: hashing them measured 127 ms over a full-budget array against 22 ms without, on an event that fires on every selection change, so a paint layer added, removed, retextured or resized is noticed and painting inside an existing one is not.
- **Numeric input**: type exact dimensions during drag or extrude (Enter applies, Backspace edits).
- **UV Justify**: fit/center/left/right/top/bottom alignment modes for selected faces.
- Bake builds a temporary CSG tree from DraftBrushes + CommittedCuts and outputs BakedGeometry. Primitives become the CSG shape `PrefabFactory.create_prefab()` builds for them, except a round one, which goes in as its own faces, so a cut anywhere does not change its tessellation; a CUSTOM brush is cut with the mesh it is drawing, because the factory falls back to a box and a vertex edit, a polygon extrusion, a bevel or an imported hull would otherwise bake as one. That is the same mesh `HFSubtractPreview` cuts with, so the preview and the bake agree. If cordon is enabled, transformed geometry bounds—not an untranslated local AABB—determine inclusion. Every brush entity class, `func_wall` included, is excluded from structural bake. Commit Cuts prepares and bakes outside UndoRedo, then stores exact source and baked snapshots for synchronous undo/redo; failed preparation leaves its cutters pending.
- Undo/redo actions prefer brush IDs and state snapshots over long-lived Node references. `restore_state()` frees and rebuilds every entity, so a step that holds one aims at a freed node once a snapshot step is undone or redone past it. A function that calls `create_action()` outside `HFUndoHelper` is listed in `DIRECT_UNDO_STEPS` (`tests/test_dock_undo_coverage.gd`) with why its step survives a restore (#1108).
- **Command collation**: `HFUndoHelper` supports a `collation_tag` parameter. Consecutive actions with the same tag and same `full_state` scope within 1 second merge into one undo entry via `MERGE_ENDS` (nudge, rotate, resize, paint). Mismatched `full_state` breaks the collation window. `MERGE_ENDS` keeps the first action's undo operations and the last action's do operations, which is correct only when that last do names an absolute final value, so commands that register a *step* pass `absolute_redo`: the method runs first and a snapshot of the result is registered as the do operation, committed without executing. Tags name the command, its targets and the inputs that change what the press means, so a changed selection, direction or axis starts a new entry rather than merging into the run before it. The same snapshot mechanism covers long argument lists: `EditorUndoRedoManager.add_do_method()` takes an object, a method name and varargs, and GDScript cannot spread an array into varargs, so `register_action()` unrolls the call by hand up to `MAX_UNROLLED_ARGS` (5) and registers a state snapshot as the do operation past that. `create_radial_array` is the only command over the limit today; before this, six arguments meant no do operation was registered at all and the command fell off the undo stack silently.
- **Multi-step operations**: there is no transaction API. Each operation records its own undo step. One that creates, deletes or moves many brushes at once batches its signals (see Signal Batching).

## Entity Definitions

Entity types and brush entity classes are data-driven via `HFEntityDef` (`hf_entity_def.gd`):
- Loaded from `entities.json` at `entity_defs_path` (default: `res://addons/hammerforge/entities.json`), overlaid with `res://hammerforge_entities.json` when present. Same classname replaces the plugin entry.
- Falls back to built-in defaults (func_detail, func_wall, trigger_once, trigger_multiple).
- Each definition has: `classname`, `description`, `color`, `is_brush_entity`, `properties`, `scene_path`.
- `HFEntityDef.load_definitions(path)` returns `Array[HFEntityDef]`. `load_merged_definitions(plugin_path, project_path)` applies the project overlay.
- `load_raw_entries(path)` and `load_merged_raw_entries(...)` return the untouched JSON dictionaries. The dock palette uses these because `to_dict()` drops the `label`, `preview` and `category` keys it renders from. Both entity pickers read the same merged set so they cannot disagree about what exists.
- `filter_brush_entities()` keeps the brush entity definitions.
- Dock brush entity class dropdown is populated from definitions, not hardcoded.
- **Presets** (`presets`, a name to property values per class): `HFEntityPropUtils.preset_names()` / `preset_values()` read them, coercing each value to its property's type and dropping one the class does not declare. The Entity panel's Preset list applies one through `LevelRoot.set_entity_properties()` as one undo step scoped to the entity; the palette adds a button per preset whose drag data carries `properties`, which `HFPluginDropHandler.handle_entity_drop()` sets on the placed entity. Lights ship Warm Ceiling, Cool Fluorescent, Practical and Sun. A property's `tooltip` is shown on its label and controls.
- **Light projector**: point and spot lights declare `projector` (a `Texture2D` path in `resource_properties`, mapped to `light_projector`) and `shadows` (`shadow_enabled`). `_apply_entity_properties_to_node()` turns shadows on for a `Light3D` that ends up with a projector, since one only shows through a shadow-casting light. Three textures ship in `addons/hammerforge/projectors/`.
- **Declarative property forms**: the `properties` array on each definition supports typed entries (`{name, type, default, label}`) that auto-generate dock controls (LineEdit, SpinBox, CheckBox, OptionButton, ColorPickerButton, Vector3 spinboxes) when an entity is selected. Changes write to `entity.entity_data` and sync the Inspector. Inspired by QuArK's `:form` system.

`HFPluginNumericInput` (`plugin_numeric_input.gd`) owns typed dimension entry while a draw or extrude is active: digits, period and Backspace edit the buffer, Enter applies it. Tools do not keep their own numeric buffer.

`MaterialManager` (`material_manager.gd`) manages the shared material palette:

## Floor Paint System

Data
- Grid -> Layer -> Chunked storage (bitset + material_ids + blend_weights + blend_weights_2 + blend_weights_3).
- Each layer optionally has a `heightmap: Image` and `height_scale: float`.
- Paint layers are stored under PaintLayers.

Tools
- Brush, Erase, Rect, Line, Bucket, Blend (enum `HFStroke.Tool`, values 0-5).
- Sculpt Raise, Sculpt Lower, Sculpt Smooth, Sculpt Flatten (values 6-9) — operate directly on heightmap Image pixels with configurable strength, radius, and falloff.
- Blend tool writes per-cell blend weights to slots B/C/D on already-filled cells.

Brush Shape
- Square: fills every cell in the radius range (full box).
- Circle: clips corners using Euclidean distance check.

Generation (flat layers -- no heightmap)
- Floors: greedy rectangle merge -> DraftBrush boxes.
- Walls: boundary edges + merged segments -> DraftBrush boxes.

Generation (heightmap layers)
- Floors: per-cell displaced quads via `HFHeightmapSynth` -> ArrayMesh -> MeshInstance3D.
- Per-chunk blend image (Image FORMAT_RGBA8) built from cell blend weights (RGB = slots B/C/D).
- Blend shader (`hf_blend.gdshader`) mixes four slots via UV2-sampled blend map (slot A implicit).
- Walls: still use flat `HFGeometrySynth` (no heightmap displacement on walls).

Reconciliation
- Stable IDs for generated geometry (floors, walls, heightmap floors).
- Dirty chunk scoping to avoid unnecessary churn.
- `Generated/HeightmapFloors` container for MeshInstance3D nodes.

Auto-Connectors
- `HFConnectorTool` generates ramp or stair ArrayMesh between two cells on different layers.
- Ramp: sloped quad strip. Stairs: horizontal treads + vertical risers.

Scatter Brush
- `HFScatterBrush` (`paint/hf_scatter_brush.gd`) scatters instances in a circle or along a spline, with a MultiMesh density preview.
- Filters by height range, slope threshold; configurable density, scale, rotation, seed.

## Region Streaming (Floor Paint)
- Floor paint chunks are grouped into regions (default 512x512 cells).
- Streaming loads regions within a radius of the cursor and unloads distant regions.
- Region files (`.hfr`) store per-region chunk data to keep `.hflevel` small.
- Region index is stored in the `.hflevel` state under `terrain_regions`.
- A region is written before its chunks are dropped. If that write fails the region stays loaded and the user is told, rather than losing unsaved paint.
- A region is only recorded as having data once its `.hfr` file is actually written. A failed sidecar aborts the `.hflevel` save instead of shipping an index that points at missing files.

## Entities
- Entities live under LevelRoot/Entities or are tagged `is_entity`.
- Entities are selectable but excluded from bake.
- Definitions come from `addons/hammerforge/entities.json`, overlaid with `res://hammerforge_entities.json` when present. The point entity palette and the brush entity dropdown both read that merged set, and the path comes from the active LevelRoot's `entity_definitions_path`.

### Entity I/O (Input/Output Connections)
- Source-style trigger/target system modeled after Hammer/Source entity I/O.
- Connections stored as `entity_io_outputs` meta (Array of Dictionaries) on entity nodes.
- Each connection: `{output_name, target_name, input_name, parameter, delay, fire_once}`.
- `HFEntitySystem` provides: `add_entity_output()`, `remove_entity_output()`, `get_entity_outputs()`, `find_entities_by_name()`, `get_all_connections()`, `fire_output()`. Adding or removing a wire on a brush entity acts on every brush of it, through `LevelRoot.entity_property_nodes()`, as properties do (#1129).
- `find_entities_by_name()` searches both `entities_node` and `draft_brushes_node` for target resolution.
- `fire_output(entity, output_name, parameter)` delegates to `HFIORuntime` dispatcher if present in the scene, falls back to direct multi-target resolution otherwise.
- I/O connections are serialized with entity info in `.hflevel` saves and undo/redo state via `capture_entity_info()` / `restore_entity_from_info()`. A full restore that cannot give a node its recorded name, an entity named `@Node3D@14` before #1179, retargets every wire aimed at the recorded name to the new one (`HFStateSystem._note_rename()`). A brush's record leaves such a name out (#660), so a brush drawn before #1065 gets its readable name as the level opens, and the wires aimed at it follow (`HFBrushSystem.name_brushes_godot_named()`, #1182).
- Dock UI: collapsible "Entity I/O" section in the Objects tab with fields for Output, Target, Input, Parameter, Delay, Fire Once. Add/Remove buttons and connection ItemList. Context-hidden (only visible when an entity is selected); auto-refreshes on selection change.
- **Viewport visualization**: `HFIOVisualizer` draws ImmediateMesh lines between connected entities. Color-coded: green=standard, orange=fire_once, yellow=selected entity connections. Throttled refresh (10 frames). "Show I/O Lines" checkbox in the Objects tab.
- **Runtime signal translation**: `HFIORuntime` (`hf_io_runtime.gd`) auto-wires `entity_io_outputs` metadata into Godot signals on bake/export. Auto-injected by `export_playtest_scene()` and optionally by `postprocess_bake()` (`bake_wire_io` export). Connections keyed by node instance ID; a brush entity gives each wire once whichever of its brushes hold it, a trigger connects every one of its volumes and fires as one, and its fire-once state is held under `@<name>` with the instance ids it was made of (#1129). One tied with no name is keyed `@#<tie>` instead: the bake carries its `brush_entity_group` onto each node it makes, as each of those answers to its own brush's node name (#1133). Both are `HFBrushEntity.baked_identity()`. Targets resolved to all matching nodes, and then to every node of each brush entity among them, so an input aimed at one leaf of a door or one brush of a trigger reaches the whole entity (#1150). A named entity's baked node also answers to the node name of the brush it came from, its `brush_node_name` meta, since the editor and the Objects tab's target list take that as an address too (#1149). A door raises `OnOpen` and `OnClose` from the whole door through `HFIORuntime.fire_door_on()`: `OnOpen` as its first leaf opens and `OnClose` as its last one shuts (#1145). Delivery cascade: a method the class grants (`input_methods`) → direct method → snake_case → `_on_io_input()` → the inputs the dispatcher answers itself (Enable/Disable on a brush entity, Press/Lock/Unlock on a button, Trigger on a `logic_relay`, TurnOn/TurnOff/Toggle on a `Light3D`) → user signal; `_deliver_to_target()` returns whether anything answered, and `tests/test_declared_inputs_answered.gd` holds every input a shipped class declares to that (#1209). A marker the export ships as itself carries its properties as an `entity_data` meta. A zero-delay wire is delivered inside the call that raised its output; past `HFIORuntime.MAX_CHAIN` (64) nested wires the rest of that chain is dropped and the loop is named once (#1218). `io_fired` and `io_received` go out once per delivery, however many nodes answer to the target (#1219). `_find_dispatcher()` walks up from a node to the dispatcher whose `wire()` scans it, so each loaded level fires its own wires; `fire_on()`, `fire_door_on()` and `press_button_on()` all use it (#1211). Source entities receive `io_<OutputName>` user signals. Delay via a `SceneTreeTimer` made with `process_always` false, so a pause holds it (#1140), fire-once tracked per-connection. `extra_scan_root_paths: Array[NodePath]` (@export) persists scan roots across scene save/reload. `_prune_overlapping_roots()` deduplicates by instance ID and ancestor/descendant relationship.

- **Trigger and button properties at runtime**: the bake carries `HFBrushEntity.properties()` onto a trigger's `Area3D` and a `func_button`'s body and mesh as `entity_data`. `trigger_multiple` holds `OnStartTouch` back for its `wait` (Quake meaning: above 0 seconds, 0 every time, below 0 once). `HFIORuntime.press_button(node)` fires `OnPressed` unless the button is locked or inside its `wait`, and a baked button answers `Press`, `Lock` and `Unlock`; wait and lock are held by name, or by the tie of one with no name (#1121, #1133). A wait is measured in game time, the frame time the dispatcher's `_process()` is handed, so `Engine.time_scale` slows it as it slows a door's `SceneTreeTimer` (#1136). A pause holds all three: the dispatcher stops adding frame time, and a door's wait is a `SceneTreeTimer` made with `process_always` false (#1140). `HFIORuntime.read_flag()` reads a flag from a bool, a number or `.map` text, for the button and the door (#1127).

### Brush Entity Classes
- Brushes can be tagged with a `brush_entity_class` meta: any class `entities.json` marks `is_brush_entity`, which ships `func_detail`, `func_wall`, `func_clip`, `func_door`, `func_button`, `door_basic`, `trigger_once` and `trigger_multiple`.
- `func_clip` (`HFBrushEntity.CLIP_CLASS`, `is_clip()`) is collision with no mesh: the bake makes each clip a convex hull on a `StaticBody3D` in every collision mode, one body per layer and one for a named clip, and it takes no part in the structural CSG, the face bake, lightmaps or occluders. It does cut the navmesh. Its `layer` property, 0 for the level's Physics Layer, is read as a number or text (#1409).
- Which brushes are one entity is decided in one place, `HFBrushEntity` (`hf_brush_entity.gd`, #1148). On a draft brush, `identity()` is the authored name when there is one and otherwise the tie (`brush_entity_group`), and `members()` is the brushes with the same class and identity. On a baked node, `baked_identity()` reads the tie first, because every node the bake makes carries a name, the brush's own for an entity with no name, and the bake writes the tie only for such an entity (`tie_to_bake()`). The bake, the runtime dispatcher, the `.map` export, the Entity panel, MCP and Validate all ask it, and `tests/test_brush_entity_rule.gd` holds them to the same entities and properties.
- A copy of a brush entity is an entity of its own. A placed prefab, a paste, Duplicate, `duplicate_brush()` and each copy in a Duplicate Array run their records through `HFBrushEntity.fresh_identities()`, which gives each tie a newly minted one (`mint_tie()`) and each authored name one of its own in the level (#1158, #1161). A placed prefab or a paste also remaps every placed node's wires to the new names and node names (#1159); a duplicate's wires stay as they were, as a duplicated point entity's do. A variant switch or a pull rebuilds a placed copy under the names it has: `HFRebuildCarry.capture()` reads its authored names and node names before it goes, keyed by the records they were placed from, and `fresh_identities()` and the record's `name` give them back (#1168, #1178). A node the rebuild made earlier that took a kept name through Godot's numbering is swapped back (`HFRebuildCarry.restore()`), on a generator Update as well (#1221).
- Tie/Untie via `HFBrushSystem.tie_brushes_to_entity()` / `untie_brushes_from_entity()`. Untie drops the brush's `entity_io_outputs` and `brush_entity_data`, and a tie as another class keeps only the properties and outputs that class declares (#1112).
- `LevelRoot.set_entity_property()` and `set_entity_properties()` write to every brush of a brush entity, grouped by `HFBrushSystem.brushes_of_entity()` as the `.map` export groups them, so the Entity panel and `hf_set_entity_properties` give a two-leaf door one speed (#1113).
- Every brush tied to an entity class, `func_wall` included, is excluded from structural bake via `HFBakeSystem.is_structural_brush()`, which Subtract Preview reads too ([#1563](https://github.com/saworbit/hammerforge/issues/1563)).
- A nonstructural brush that is not a trigger keeps a node of its own after the bake when it has wires, an `entity_name`, a class that declares inputs or outputs or moves, or a node name a mapper typed; the rest group into one mesh per material and one body (#712), a mesh for each Cast Shadows and Lightmap Scale among them (`HFBakeSplit`, #1444, #1438). The readable name a brush is given (`Box_3`) is not one a mapper typed, as `HFBrushSystem.has_readable_name()` says (#1139), whatever shape's label it carries, so a bevelled or vertex-edited brush, now CUSTOM, still groups (#1144). Each brush of a named entity after the first bakes under its own brush's node name, `Box_7`, which it answers to already through `brush_node_name` (`HFBakeSystem._add_piece()`, #1169). Godot's `@Node3D@20` was unreadable, and its readable `gate2` would be an address another entity may hold, since `HFIORuntime` caches every baked node by its node name.
- The `.map` export writes brushes tied under one name or one tie as one entity, with a brush block per brush, its name once, and each wire and property any of its brushes holds once (#1128). The import gives the brushes of each entity block one `brush_entity_group`, so an unnamed entity comes back tied (#1134). A wire aimed at a brush by its node name is written aimed at its entity's address in the file, `MapIO._file_addresses()`: the entity's name, or for one with no name the node name of its first brush, which its block then carries as `targetname` (#1155), or the next name free in the file by `unique_authored_name()`'s rule when something else answers to that one (#1229).
- Validate's duplicate name check counts the brushes of one tie as one entity, by `HFBrushEntity.tie_key()`, so a two-leaf door tied under one name is not reported, while two ties under one name still are (#1151).
- Visual indicators: `func_detail` = cyan tint, `trigger_*` = orange tint, `func_clip` = violet tint whatever its faces carry (semi-transparent overlay in `brush_instance.gd`, marked as an editor look so it never reaches a bake).

## Persistence (.hflevel)
- Stores brushes, entities, level settings, materials palette, and paint layers.
- Brush records include face data (materials, UVs, paint layers, `smoothing_group`, and `uv_group` on a linked face), visgroup membership, group_id, `brush_entity_class`, and `bake_cast_shadow` and `bake_lightmap_scale` when the brush sets its own (`HFBakeSplit.fields()`).
- Entity records include visgroup membership, group_id, `io_outputs` (Entity I/O connections), and, on a linked prefab copy's entity, the `prefab_entity_id` a Pull finds it by. A prefab or a duplicate does not carry it.
- Paint layers include grid settings, chunk size, bitset data, `material_ids`, `blend_weights` (+ _2/_3), and terrain slot settings.
- Optional per-layer: `heightmap_b64` (base64 raw float buffer, zstd compressed; a base64 PNG from an older version still loads), `height_scale`. Missing keys = no heightmap (backward-compatible).
- Level settings include `texture_lock`, `export_level_environment`, `cordon_enabled`, `cordon_aabb_pos`, `cordon_aabb_size`, `cordon_aabb_name`, `cordon_aabb_active`, `cordon_extra_aabbs` (a list of `{"pos", "size", "name", "active"}` dictionaries), `bake_cast_shadows`, `transform_pivot_point`, `mirror_copy_axes` and `mirror_copy_at_edge`. `active_material` is saved with the scene, not in the file, because it is the next brush's material. A missing `cordon_extra_aabbs` leaves the level's extra cordons as they are. A cordon the file holds with no name or switch is unnamed and on.
- Visgroup definitions and group registry stored in state via `capture_visgroups()` / `capture_groups()`.

## Bake Pipeline
- Temporary CSG tree for DraftBrushes (including generated flat floors/walls).
- Heightmap floor meshes are duplicated directly into baked output (bypass CSG) with trimesh collision shapes.
- Chunked baking (default `bake_chunk_size = 32`): groups brushes by grid coordinate, bakes each chunk independently.
- Owner assignment uses `_assign_owner_recursive()` after the baked container is added to the tree (avoids premature owner errors during chunked bake).
- Optional mesh merging, LODs, lightmap UV2, navmesh.
- Optional face-material bake (per-face materials without CSG) only when no effective structural subtractor exists; any pending/applied/frozen cut forces CSG so rendered geometry and collision preserve the boolean result.
- **Automated occluder generation** (`bake_generate_occluders`): `postprocess_bake()` scans all baked `MeshInstance3D` nodes (recursing into `BakedChunk_*` intermediary nodes), groups coplanar triangles by normal (5° threshold) and plane distance (0.1 unit threshold), and creates `OccluderInstance3D` with `ArrayOccluder3D` per group exceeding `bake_occluder_min_area` (default 4.0 world units²). Occluders are parented under an `Occluders` Node3D child of the baked container. Idempotent — re-bake replaces previous occluders.
- Collision uses Add brushes only.
- Navmesh defaults: `cell_height = 0.25` (matches Godot NavigationServer3D map default).
- Navmesh parse: the baked container's static colliders, less the bodies of `MOVER_CLASSES` holders, which go to layer 0 for the parse only so a doorway stays walkable (#1196), plus each entity the export would build with a static collider, such as a `prop_static`, stood in under a `NavmeshProps` node that is freed straight after (#1197).
- **Bake Selected** (`bake_selected()`): bakes only selected brushes and merges output into the existing `baked_container` (does not replace it). Each piece of the bake records the brush ids it holds (`BAKED_BRUSH_IDS_META`: on the container for a full bake, on each `BakedSelection_*` node for a selection). An earlier selection holding a selected brush is removed and its other brushes baked again with the selection; a selected brush the full bake holds, or any brush when a bake piece has no record, turns the call into a full bake.
- **Bake Changed** (`bake_dirty()`): bakes the whole level when a brush has a dirty tag (`_dirty_brush_ids`) or painted ground has dirty chunks (`_dirty_paint_chunks`, tagged by every paint reconcile; a regenerate tags a full reconcile), and does nothing when nothing changed. It rebuilds in full because a correct CSG result needs every brush, so what it saves is the bake when nothing has changed (#1593). With the navmesh on it also rebakes when a prop the navmesh is cut around changed: `navmesh_props_signature()` (the class, properties and transform of each entity whose class builds from a scene, such as `prop_static`) is compared with the last successful bake's, so a prop moved, added, deleted or given another Scene counts however it was edited. The paint connectors the mapper kept (`connector_defs_signature()`, the paint tool's `capture_connector_defs()`) are compared the same way, so a connector confirmed, undone, redone or reloaded rebakes. A run claims its starting tags; failure restores them, while edits tagged during the asynchronous run remain queued for the next bake.
- **Preview modes** (`PreviewMode` enum: FULL, WIREFRAME, PROXY): `_apply_preview_visuals()` overrides material on baked meshes. Wireframe uses inline `ShaderMaterial` with `render_mode wireframe`. Proxy uses unshaded semi-transparent `StandardMaterial3D`.
- **Bake time estimate** (`estimate_bake_time()`): `_last_bake_duration_ms` over `_last_bake_brush_count`, the brushes that bake took (the selection's for a Bake Selected, the level's for a full bake), times the brushes to bake now, or 2 ms a brush before any bake (#1590). Over 500 brushes its tip says to chunk the bake so the game can cull it; chunking does not make the bake shorter (#1593).
- **Bake issue list**: `HFDockManageHandler.on_bake_check_issues()` adds `HFSpawnSystem.layout_issues()` (a missing spawn; a spawn inside a brush, by `spawn_is_blocked()`, which clips the line the player capsule stands on against each brush's face planes and takes away what a later cutter covers, skipping triggers; `validate_spawn()` asks it too and then reports only `IN_BRUSH_ISSUE`, suggesting `clear_place_for()`; its floor is the higher of the ray's hit and `_brush_floor_under()`, the brush floor read from faces, so it needs no bake to find one, #1059) to the bake issues and lists them all under Check Bake Issues through `show_bake_issue_list()`. A row with a `node` gets Select; a row whose `fix` is in `BAKE_ISSUE_FIXES` gets Fix, which runs `on_spawn_auto_create()` or `move_spawn_clear()` as one undo step (through the dock's `_commit_spawn_create()` / `_commit_spawn_move()`) and checks again. `clear_place_for()` searches with `_clear_place_near(..., same_floor = true)`, so a spawn upstairs stays upstairs.
- **Bake issue detection** (`HFValidationSystem.check_bake_issues()`): returns Array of `{type, severity, message, node}` dicts; a micro-gap also carries `other_node`, the second brush of the pair. Checks: degenerate brush (sev=2), oversized (sev=1), floating subtract (sev=1), overlapping subtracts (sev=1), non-manifold edges (sev=2), open edges (sev=1), non-planar faces (sev=1), micro-gaps between brushes (sev=1), occlusion coverage (sev=0 info or sev=1 warning). Non-planar detection uses `planarity_tolerance` (default 0.01). Micro-gap detection uses `weld_tolerance` (default 0.001), and counts a pair closer than float32 rounding (`_touching_distance()`: 1e-5, or a millionth of the coordinate) as touching. Both use 27-cell spatial hash neighbor lookup for boundary-safe distance checks. Floating-subtract and overlapping-subtract share one broad phase: every world AABB is built once, then a sort-and-sweep along the axis the level is widest on visits only the brush pairs that overlap on that axis, so distant brushes never reach an AABB test. `_edge_key()` for topology (non-manifold/open-edge) uses fixed 0.001 precision, intentionally decoupled from `weld_tolerance`.
- **Auto-fix helpers**: `weld_brush_vertices(brush)` snaps near-coincident vertices within `weld_tolerance` via BFS grouping + `ensure_geometry()` refresh. `fix_non_planar_faces(brush)` projects drifting vertices onto the best-fit plane from each face's first 3 vertices.
- **Playtest export** (`export_playtest_scene()`): packs baked output, brush entities, point entities, the starter's `DefaultSun` and `TempFloor` (in a game scene too, #1042), default lighting/environment, and a player controller positioned at the active spawn. Test Level adds the same `PlaytestEnv` and `PlaytestSun` when nothing in the running scene sets an environment or lights it (`_light_like_a_playtest_export()`, #1047). `find_level_environment()` returns a `WorldEnvironment` under LevelRoot or beside it at the top of its scene; a playtest packs it in place of the flat `PlaytestEnv`, and a game scene packs it only with `export_level_environment` on (an `.hflevel` setting, the dock's **Include Level Environment**). Reparented content keeps its world transform, nested geometry/collision receives recursive scene ownership, and `HFIORuntime` is injected when connections exist.

## Face Materials + Surface Paint
Face data is stored per DraftBrush face with material assignment, UV projection, and optional paint layers.
Surface paint is a per-face splat system. It updates preview materials and can be baked using the face-material bake option. Alt on the press makes a stroke erase. A stroke is one undo step: `HFPaintSystem` records each brush with `capture_brush_scope()` before the stroke first paints it, and `HFPluginPaintInput.commit_surface_paint_undo()` commits the merged scope on release, or when gesture recovery closes the stroke. A stroke that starts on a pending cut records the whole level instead; one that reaches a pending cut part way through stops at it.

## Data Flow

```
Godot editor input and UI
  -> plugin.gd                  (lifecycle, composition, discovery, undo wiring)
     -> plugin_*.gd             (viewport, numeric entry, selection, commands, HUD, overlays, edits, drops)
     -> HFToolRegistry          (plugin-owned built-in/external tools)
     -> dock.gd
        -> dock_*_handler.gd    (tab workflows, files, visgroups, connections)
     -> level_root.gd           (public level facade and cross-system coordination)
        -> runtime core         (brush, entity, bake, paint, file)
        -> editor-only graph    (drag, grid, snap, state, validation, previews, authoring tools)

HFLevelFactory                  (makes a LevelRoot from code; no dock, no EditorPlugin)
  -> level_root.gd
```

`LevelRoot` preserves the public level API used by `plugin.gd` and `dock.gd` (`root.bake()`, `root.begin_drag()`, and similar operations). It delegates cohesive behavior to subsystems while retaining container ownership, exported settings, signals, runtime lifecycle, and cross-system coordination; its methods are therefore not uniformly one-line delegates.

`HFLevelFactory` makes the root itself, which is the one step that sits in front of that API. `create_level_root(parent)` adds an empty `LevelRoot`, and `create_starter(parent)` adds one and fills it with the floor, sun and player spawn that Create Starter builds. Both take an optional owner and an optional property dictionary applied before `_ready`, since `LevelRoot` reads its exports there and outside the editor a fresh root would otherwise start a playtest. `plugin.gd` exposes `create_starter_level()` for the same result in the scene the editor has open, as one undo entry.

`plugin.gd`'s `_forward_3d_gui_input()` is a two-line boundary that delegates viewport arbitration to `HFPluginViewportInput.handle()`. That module coordinates the focused paint, keyboard, RMB, selection, extrude, draw, motion, vertex, and external-tool paths. Numeric dimension parsing, live preview, and draw/extrude commit live in `HFPluginNumericInput`. Other `plugin_*.gd` modules similarly own selection state, commands, HUD state, overlays, edit actions, and viewport drops.

## Selection and Gizmo Arbitration
- Godot's visible `EditorSelection` is authoritative, including an empty selection. HammerForge mirrors it instead of retaining a hidden stale cache; the deprecated `should_suppress_empty_selection()` compatibility helper always returns `false`.
- Every ordinary Object Select LMB press uses Godot's native viewport pipeline for click, empty-space marquee, modifiers, gesture threshold, and complete transform/property-widget ownership, including keys such as Escape and Ctrl+Arrow while the claim is active or opaque. Shift retains Godot's native additive/active-selection behavior; Ctrl/Cmd stay Godot-owned and are not reinterpreted as a HammerForge Object Select toggle. Brush gizmos contribute exact filled face triangles plus semantic collision segments; entity gizmos combine every healthy preview triangle with restrained null/line-only sibling markers, preserve top-level child transforms in entity-local space, and respect hidden ancestors. A truly geometry-less `DraftEntity` gets a quiet one-unit box target, while a deliberately hidden/empty preview gets no invisible fallback.
- Face Select is modal. Entry selects the built-in Select tool, disables Paint, snapshots and clears the object `EditorSelection`, and hides Godot transform plus HammerForge resize gizmos before any face press can overlap them. Manual exit clears faces and restores valid snapshot nodes. Leaving Paint, switching to an incompatible built-in/external tool, or entering vertex edit closes the mode through the same restore path. A new native/Scene-tree object selection exits Face Select and keeps that new object instead of restoring the snapshot. Escape clears selected faces first, then exits/restores on the next press, or exits immediately when there are no selected faces.
- Face clicks and marquees use HammerForge's visible-face logic with `AFTER_GUI_INPUT_CUSTOM`, which suppresses competing node/region selection but still lets Godot finish custom gizmo cleanup. Shift adds and Ctrl/Cmd toggles. Marquee candidates must be canonical visible brush faces with projected centers in the rectangle, and the canonical ray pick at each center must identify that same brush/face as the frontmost visible hit. With X-ray on (the checkbox beside Face Select Mode, Alt+X) the pick is skipped and every candidate whose center is in front of the camera is taken, covered or facing away (#1432); the HUD names it and the rectangle is drawn amber.
- Deferred normalization maps internal preview hits to their HammerForge owner and expands grouped nodes as a unit. `classify_selection_scope()` passes native-only keyboard actions through, applies managed commands only to HammerForge-only selections, and blocks mixed selections with a warning. The same mixed-selection guard applies to context-toolbar, viewport-context-menu, hotkey-palette, and radial dispatch, with selection-dependent UI unavailable instead of offering a partial HammerForge edit.
- Delete, Duplicate, and nudge treat canonical `DraftEntity` nodes as managed selections alongside brushes. `LevelRoot` delegates each domain to its owning system under one undo action; entity duplication retains entity data and group/visgroup membership, and a duplicated brush entity takes a tie and a name of its own (#1161), while deletion cleans group/visgroup membership and dangling I/O connections.
- Brush AABBs are broad-phase only for HammerForge pickers. The final object, hover, face-tool, and editor-placement fallback uses actual visible face triangles, so empty space inside a wedge, cone, pyramid, curved, or custom brush cannot select, occlude, or receive a dropped item. Brush/entity candidates share one world-ray distance comparison, including under non-uniform scale.
- Hover, selected gizmos, and subtract operation styling share `DraftBrush.get_editor_outline_lines()`: angular/custom shapes retain boundaries and true creases without coplanar triangulation diagonals, curved primitives use sparse semantic profiles rather than render cages or fallback boxes, and degenerate planar/linear bounds emit no duplicate or zero-length lines.
- Resize handles are shape-aware as well as transform-aware. Spheres couple X/Y/Z, cylinder/cone/capsule X/Z handles couple the radial axes, capsule Y stays at least its diameter, and all shapes snap world extents while anchoring the opposite face under rotated/non-uniformly scaled parents. Odd-sided prisms and adjustable pyramids use one centered AABB-normalized polygon contract across preview, outline, bake, and handle bounds.
- Buttonless motion and application/window focus loss recover stale native selection, RMB, paint, vertex, and handle ownership. A lost custom-handle release restores/freezes its preview, releases the local latch after a bounded deferred turn if Godot never commits, and suppresses any late callback so it cannot mutate geometry or create undo.

## Customizable Keymaps

All keyboard shortcuts are data-driven via `HFKeymap` (`hf_keymap.gd`). Plugin loads bindings from `user://hammerforge_keymap.json` (or built-in defaults). Each binding maps an action name (e.g. `"hollow"`) to `{keycode, ctrl, shift, alt}`. Plugin uses `_keymap.matches(action, event)` instead of hardcoded `KEY_*` checks. Three kinds of key are not bindings. `HFKeymap.GODOT_EDITOR_KEYS` are the chords Godot's editor answers wherever the focus is (Undo, Redo, the scene file keys, Quit, F5 to F8); the router and the vertex keys pass them to Godot ahead of every binding, and `conflicts_for()` reports a binding on one as `godot_editor` (#1617). `HFKeymap.FIXED_KEYS` are the keys the router takes ahead of every binding, read through `fixed_key(event)`: the command palette (F1, Shift+/ and Ctrl+K), Escape, and nudge; `conflicts_for()` and the load-time warnings report a binding on one of them (#1614). `HFKeymap.HOLDS` are keys read while held, through `held()`: the snap-invert hold (Ctrl) and the vertex-snap hold (Alt), left out of `get_actions()` (#1431). In Paint mode the paint actions are asked before every general action except the eight in `EVERY_MODE`. Toolbar labels and tooltips pull display strings from the keymap. An action's label and category come from `HFCommandRegistry` (#1265).

## User Preferences

`HFUserPrefs` (`hf_user_prefs.gd`) stores cross-session application-scoped preferences in `user://hammerforge_prefs.json`. Separate from per-level settings on LevelRoot. Includes: default grid snap, recent files (max 10, most recent first), collapsed section states, HUD visibility, the welcome panel, power-user overlays, the viewport switches `size_at_cursor`, `draw_hover_preview` and `show_selection_size`, dismissed hints (coach marks among them, as `coach_dismissed_*`), favourite materials, recent materials (`recent_materials`, the last eight applied, newest first), the tutorial step, saved bake profiles (`bake_profiles`, name to options), the UV Editor's `uv_scale_linked`, `uv_snap_enabled` and `uv_snap_step`, the settings each tool was last used with (`tool_settings` by tool, `build_settings` for the Build tab's controls and snap toggles, `structure_settings` for the Structure section's type and each type's fields, all held to their schemas on read, #1406), and the seventeen overlay colours (`color_*`, hex strings) that `hf_overlay_colors.gd` reads every selection, hover, brush look, brush entity look, cordon and extrude overlay through. ## Tag-Based Invalidation

LevelRoot maintains dirty tags for selective reconciliation:
- `tag_brush_dirty(brush_id)` — marks a specific brush as needing rebuild.
- `tag_paint_dirty(chunk_coord)` — marks a paint chunk as dirty.
- `tag_full_reconcile()` — marks entire scene for full rebuild (structural changes like hollow/clip).
- `consume_dirty_tags()` — returns and clears all tags (called by reconciler).

Brush system calls these on create/delete/transform/hollow/clip.

## Signal Batching

LevelRoot supports batched signal emission for multi-brush operations:
- `begin_signal_batch()` / `end_signal_batch()` with depth-counted nesting.
- During batch, signals are queued. On flush they are emitted in order, with exact repeats of the same signal and argument dropped. Lifecycle events are emitted as themselves: a batch that removes brushes emits `brush_removed`, so caches and spatial trees hear about it.
- `discard_signal_batch()` drops the queued signals without emitting them.

## Tool Poll System

`HFEditorTool` exposes `can_activate(root)` and `get_poll_fail_reason(root)`. Dock uses these to gray out buttons and set tooltips. Plugin guards keyboard shortcuts with early-exit when poll fails (e.g. Hollow requires selection).

## Declarative Tool Settings

External tools expose `get_settings_schema()` → Array of `{name, type, label, default, min, max, options, hidden}`. Supported types: `bool`, `int`, `float`, `string`, `enum`, `color`. Dock `rebuild_tool_settings()` auto-generates controls from the schema, except for a `hidden` setting. `get_setting(key)` / `set_setting(key, val)` for storage; an enum's value is its option's index. Every schema setting is kept in the user preferences between sessions under the tool's name (#1406).

## Validation + Diagnostics
- Validate Level scans for missing materials, zero-size brushes, invalid face indices, and paint layers without grids.
- `HFValidationSystem.validate()` returns `issues` (text, unchanged, which the Console, the status board and the count read), `fixed`, and `findings`: the same findings as `{type: "validate", severity: 1, message, node}` through `_found()`. `node` is the brush or entity a finding names (for two coincident brushes or a shared id, the second; for a wire to nobody, its source), or null for a count. `HFTraversalCheck.findings()` adds `steep_stairs`, `small_doorway` and `steep_ramp` findings, each with `node` and `other_node`, measured against `HFPlayerMetrics.standing()`, the playtest player's own exported defaults, which `hf_get_status` reports too (#1046). Boxes are measured in the turn about the vertical they share (#1087); boxes turned different ways step through `_turned_steps()`, which compares their outlines from above (a step meets the lower box across the player's width, and neither outline lies wholly inside the other), so a spiral of boxes is checked (#1095). One walk in `_stairs()` follows both kinds of step until a flight folds back, so a flight that turns partway is one finding (#1104). Boxes in one turn step where a face meets a face, or where the higher one starts on the lower one's top and runs on past it; a step that reaches past a step between, the same way, is dropped (#1118). `run_validation()` passes `findings` to `show_bake_issue_list()`, so a Validate press replaces the rows a Check Bake Issues press left, and a clean pass clears them.
- Auto-fix clears invalid face selections, resets invalid face material indices, and rebuilds missing layer grids.
- Bake Dry Run reports counts and chunking without generating geometry.
- Performance panel shows active brush count (with ProgressBar), entity count, vertex estimate, paint memory, bake chunk count, last bake time, recommended chunk size, and health summary (green/yellow/red).

## Agent Bridge (MCP)
- `addons/hammerforge/mcp/`: `HFMcpListener` (a `Node` the plugin owns while the Test tab's Agent Bridge box is ticked; `TCPServer` on 127.0.0.1 port 0, polled in `_process`, one command at a time), `HFMcpDispatcher` (target, revision, operation cache, the capture, apply, `commit_completed()` or restore wrapper, and create starter, undo and redo), `HFMcpTools` (each tool's argument checks and facade calls, and brushes and the palette as plain data), `HFMcpProtocol` (framing and argument readers), `HFMcpHost` (what the dispatcher asks of the editor). `plugin_mcp.gd` builds the editor's host and wires the panel (`ui/hf_mcp_panel.gd`).
- Frames are a 4-byte big-endian length and UTF-8 JSON. The first frame is a hello with the token from `res://.godot/hammerforge_mcp/discovery.json`, which the listener writes on start and deletes on stop. The folder is closed to other users first (0700, or the user alone on Windows). If it cannot be closed, the listener writes no token and goes to FAILED, naming the folder (#1109).
- Every change is one undo step named `MCP: <verb>`, recorded through `HFUndoHelper.commit_completed_if_changed()` so the facade method's own result reaches the agent. A call that left the level and the cordons as they were records no step, leaves the revision where it was and answers `no_change: true`, and `hf_batch` does the same for its ops together (#1365). A failed change restores the captured state and records nothing. The capture holds the cordons beside the level (`capture_cordons()`), because `capture_state()` does not: a refusal puts them back when they moved, and a batch's step that moved them restores them at both ends through `commit_completed_if_changed(..., cordons_before)` (#1300).
- `hf_get_cordons` lists the cordons as `HFMcpTools.cordons_dict()` (index, name, min, max, active, with `enabled` and `partial_bake`). `hf_set_cordon` adds one (no `index`, and `brush_ids` through `set_cordon_from_selection()` or `bounds`) or changes one by index, and `hf_remove_cordon` takes one out through `remove_cordon_region()`. With a place and no index on a level that holds only the untouched default cordon (one, at `LevelRoot.DEFAULT_CORDON_AABB`, unnamed, its own switch on), `hf_set_cordon` writes index 0 instead and answers `replaced_default: true`, as the dock's Set from Selection does (#1367). Their `MUTATING` entries carry `cordons: true`, so each step holds the cordons alone (`HFUndoHelper.commit_cordons()`), as the dock's cordon edits do, and an edit that leaves them as they were records none. Every edit emits `settings_applied`, or the dock's next spin nudge writes its stale bounds back (#968). A cordon given a place switches cordons on through `LevelRoot.set_cordons_enabled()`, as Add from Selection does.
- `target_id` is `<pid>:<scene root id>:<LevelRoot id>`. A change whose `expect_target` no longer matches is refused with `target_changed`.
- The revision counts `version_changed` on the scene's undo history and the global one. `UndoRedo.get_version()` cannot stand in: it falls on undo and repeats after undo then commit.
- `hf_undo` and `hf_redo` act on the scene history only when its top (or next) step starts `MCP: ` and the revision is still the one the agent's last answer carried, so a human edit, even one undone again, ends the agent's undo chain.
- New facade calls the bridge uses and the UI can share: `LevelRoot.set_brush_rotation_by_id(id, degrees)` (absolute Euler XYZ, through `HFTransformSystem.set_rotation()`), `LevelRoot.extrude_face_info(id, face_index, distance)` (the Extrude tool's brush without the drag, via `HFExtrudeTool.build_extrude_info()`; `extrude_shape()` lays a box on a rectangle not square to its brush, #1107, and makes a prism of any other outline, #1123; every face of the new brush takes the source face's texture through `FaceData.copy_texture_from()`, carried in the create dictionary so a redo keeps it, #1135), and `HFLevelFactory.create_starter_undoable()` (Create Starter as one undo step).
- `hf_bake` bakes the whole level through `LevelRoot.bake_whole_level()`, as Export Game Scene does, then writes `<scene>_mcp.tscn` through `LevelRoot.export_game_scene(path, metadata)`, the metadata (`hammerforge_bake`: bake id, source revision, target, time, `partial`) on the scene root. With `cordons: true` it bakes through `LevelRoot.bake()` instead, so only what the switched-on cordons take goes in, and the metadata, the answer and `last_bake` list those `cordons`; it is refused when `partial_bake` is false, since `bake()` would take the whole level (#1317). It records no undo step of its own; the pending cuts it applies go in first as a step of the agent's own, `MCP: apply pending cuts`, which moves the revision and which `hf_undo` takes back (#1353). `hf_batch` is the change wrapper around several checks and applies with one capture and one commit; `"$N.brush_id"` in an op names the brush op N made.
- The listener emits `command_finished(method, ok, code, ms)` for each answered command, and the panel shows the last one under its status line, status calls left out.
- A hello with `"role": "observer"` is let in beside the agent rather than in its place, up to four; it gets status and `bad_request` for anything else. `hammerforge-mcp --check` connects as one (#1060). Status is answered as it is read, after the queued work before it has started, never behind a running command (#1049).
- `hf_get_status` carries `player` from `HFPlayerMetrics.standing()` (the playtest player's exported defaults, which Validate's traversal checks read too) and the last `hf_validate`'s counts with `validation_revision`; it never runs Validate itself (#1045, #1048).
- `hf_place_entity` places a point entity (a definition with a node `class`, not `player_start`) with its declared properties, a preset and an authored name, as one step; `hf_get_entities` lists them as `HFMcpTools.entity_dict()` (#1051), outputs included. `hf_transform_entity`, `hf_set_entity_properties`, `hf_delete_entity` and `hf_add_entity_output` take an entity by that path and are one step each, refusing the spawn; properties are checked as placing checks them, and a wire's output and input must be ones the source's and target's classes declare, while a target that is not there yet is kept for Validate to report (#1082, #1083). `hf_remove_entity_output` takes a wire back by its index in the source's outputs (#1096). `hf_set_brush_entity` gives a brush a class the definitions mark `is_brush_entity` through `tie_brushes_to_entity()`, keeping its name when none is given; it takes `brush_ids`, tied as one entity, and class `none` unties them (#1105); both output tools and `hf_set_entity_properties` take a `brush_id` source in place of `entity`, and `hf_get_brushes` lists each brush's `brush_entity`, null for plain geometry (#1098). A batch op can name what an earlier op placed as `$N.entity`. `hf_viewport_screenshot` frames a box by its projected corners, looks from `focus.look_from` or an explicit `camera`, and leaves `hide` brushes or every cut out by moving their drawings to render layer 20, which the shot camera does not draw (#1040). `show: "baked"` moves every brush there and so draws only the baked geometry, refused as `no_bake` before a bake (#1084). `hf_place_brush` takes a `name`, numbered on by Godot when a sibling has it (#1086).
- `hf_list_commands` and `hf_run_command` reach the palette's commands through `HFCommandRegistry`: an entry with a `bridge` part names a parameter form in `mcp/hf_mcp_commands.gd` (`check_<form>(root, targets, params)`, the same `{ok, scope_ids, apply}` contract as the other tools), with the brushes and entities it takes and its params. A form takes the LevelRoot only, so it cannot read the selection; every id is resolved by `_read_brush()` or `_read_entity()` and one that does not resolve refuses the command. It asks the facade check the palette asks before its dialog (`can_hollow_brush`, `can_clip_brush`, `can_carve_brush`, `can_merge_brushes`, `can_intersect_brushes`, `can_snap_to_grid`, `can_build_generator`) and opens no dialog. The answer's `made` and `removed` are read off the level either side of the change, and the facade's warnings come back in `warnings`. Each run that changes the level is one `MCP: <label>` step and may be an `hf_batch` op (#1265). `update_structure` and `detach_structure` name a structure by `generator_id`, which survives the new brush ids every rebuild gives its pieces; an `update_structure` that `update_changes_nothing()` vouches for rebuilds nothing and answers `no_change: true` (#1368); Update reads its settings over the record's, not the defaults, and `hf_get_brushes` gives each piece's `structure` through the record rather than the brush's `hf_generator_id` tag, which only points at it (#1302). A restore takes the tag off any brush no restored record lists (#1306). `place_prefab` places a library prefab by file name through `HFPrefabSystem.place()`, the placement a drop and the viewport menu use, at the frame `Transform3D(turn, position)` with each piece at frame times record, which is what variant switching and propagation read back off the nodes (#1301). The copy's turn also turns what its pieces keep as a facing in their data, a door's move angle and a spawn's yaw, through the calls HF Rotate makes, on placing and on every rebuild. Floor paint is on the bridge through four of the Paint entries (#1299): `paint_ramp` (form `paint_rect`), `paint_raise` (`raise_rect`), `paint_room` (`stamp_room`) and `paint_confirm_connector` (`confirm_connector`) take a layer by index or name and cells as `[x, z]`, and call `HFPaintSystem`'s cell-space calls (`paint_cells`, `raise_cells`, `stamp_room`, `confirm_connectors`), which write the layer through the same per-cell calls a stroke does and reconcile the chunks they dirtied; the rectangle's cells come from `HFPaintTool.rect_cells()` and a confirmed definition goes through `HFPaintTool.add_connector_defs()`, both shared with the tool. The step holds the paint layers, the active layer and the connector definitions, as the palette's paint steps do. Design: `docs/superpowers/specs/2026-10-21-floor-paint-bridge.md`.
- The Python server is `hammerforge_mcp/` (`mcp>=2.3,<3`, stdio). It lists three MCP prompts (`block_out_room`, `review_level`, `bake_for_playtest`), logs one line per call, and `hammerforge-mcp --check` connects once and prints a client configuration with the interpreter's absolute path. Its version follows the addon's (`0.4.1.dev0` beside `0.4.1-dev`), and `--check` prints the tagged install line when the two are apart (#1055). The full protocol and the tool mapping are in `docs/superpowers/specs/2026-10-11-mcp-bridge-design.md`; the user's page is `docs/HammerForge_Agent_Bridge.md`.
